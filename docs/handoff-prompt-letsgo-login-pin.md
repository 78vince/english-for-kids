# Handoff：登入使用者加入數字密碼（App 端）

*撰寫：2026-10-12（內容端，依使用者需求）｜執行對象：App 端 `app/`（`profile.ts`、登入／選擇使用者畫面、`storage.ts`、`server/server.mjs`）｜內容端不改 App 程式*

## 需求
- 選擇使用者後要輸入**數字密碼**才能進入。
- 三位現有使用者（Nolan、Scott、Vincent）的密碼已由 App 端設定完成；為避免明碼留在文件中，密碼表已刪除，之後的密碼變更一律在 App 內處理。

## 建議做法
1. **不存明碼**：以 salt＋SHA-256（Web Crypto `crypto.subtle`；非 https 的區網環境可能不能用 `subtle`，請準備純 JS 備援）存成 `pinHash`／`pinSalt`，放在 profile 紀錄（`levelUnitReview.profiles.v1`，會同步到電腦與其他平板）。三位現有使用者在升級時自動寫入密碼的雜湊；原始碼與 json 內不要留下明碼（可用一次性遷移腳本產生雜湊後貼入）。
2. **輸入介面**：點使用者頭像 → 數字鍵盤（大按鈕、顯示圓點，不跳出系統鍵盤，平板好按）→ 輸入滿位數自動驗證；錯誤時搖動提示並清空；可返回重選使用者。位數不固定（目前都是 5 碼），需要「確定」鍵或比對雜湊後自動通過。
3. **連續輸錯**：連錯 5 次鎖 30 秒（本機計時即可）。
4. **記住登入**：同一裝置通過後，該分頁／主畫面 App 在一段時間內不重複輸入（例如直到「切換使用者」或超過 12 小時；請選一個並告知內容端）。「切換使用者」要清除記住狀態。
5. **新增使用者**：新增時必須設定密碼（輸入兩次）；之後提供「變更密碼」（需先輸入舊密碼）。刪除使用者仍要先輸入該使用者密碼。
6. **同步與相容**：profile 清單是「各設備取聯集」，加入 `pinHash` 後請確認伺服器合併時不會遺失；舊版沒有 `pinHash` 的紀錄視為尚未設密碼，登入時要求先設定。
7. **範圍**：這是家用區網的輕度保護，用來避免孩子互相誤用帳號；不是高強度安全機制，不需要加伺服器端驗證。

## 驗收
- 三位使用者用上表密碼可登入，輸錯進不去；連錯 5 次鎖定 30 秒。
- 電腦與平板：在一台新增／變更密碼，另一台重新整理後同樣生效。
- 舊使用者資料（進度、代幣、角色）登入後完全不受影響。
- 原始碼、`learning-data/store.json`、console 都找不到密碼明碼。
