# 遊戲星等評鑑機制——提示詞（給其他開發單位參考）

> 本文件整理「英語學習 App」遊戲室裡「填字遊戲」的星等評鑑機制設計，供其他開發單位在自己的專案裡實作類似機制時參考。內容包含設計理念、計算公式、儲存規則、UI 呈現慣例與可調整參數，附完整虛擬碼，語言/框架無關，可直接套用到任何遊戲類型。

---

## 一、設計理念

1. **不用時間或速度當評分指標**。整個 App 的教育理念是讓兒童在沒有時間壓力的情境下學習，因此星等刻意不採用「完成得多快」，而是採用「過程中答錯了幾次」——這個指標跟操作快慢無關，只反映「有沒有掌握內容」，比較貼近學習成效，也不會讓小朋友因為手速慢而感到挫折。
2. **累計整個遊戲流程的表現，不是單一回合**。這款遊戲設計成「同一份內容玩 N 個難度遞增的關卡」，星等是等到**全部關卡都破完**之後，用「全部關卡加總的錯誤次數」一次算出最終星等，不是每一關各自評分。這樣設計的理由：如果每關獨立評分，玩家會傾向在簡單關卡（提示多）刷高分後就不想挑戰後面的難關；用總表現來評分，才能鼓勵玩家願意面對困難關卡。
3. **只記錄「最佳紀錄」，不會因為表現變差被洗掉**。每個玩家、每一款遊戲各自累積一個「最高星等」，新的一輪如果表現不如之前，最高紀錄不會被降級——「最高紀錄」這個詞的直覺意義就是「歷史最佳」，不是「最近一次」。

---

## 二、計算公式

### 2.1 門檻式評分（不是連續分數）

不用連續分數（例如「正確率 87%」）當作星等依據，而是把「總錯誤次數」切成幾個門檻區間，每個區間對應固定的星等。原因：
- 門檻式評分容錯性高，答錯 1 次跟答錯 2 次感覺上差不多，不需要精細到小數點的分數。
- 門檻的數字很容易依照實際遊戲難度事後微調，不需要牽動任何其他邏輯。

### 2.2 目前採用的 5 級門檻（1-5 顆星）

| 總錯誤次數 | 星等 |
|---|---|
| 0 次 | ★★★★★（5 顆星） |
| 1～2 次 | ★★★★☆（4 顆星） |
| 3～4 次 | ★★★☆☆（3 顆星） |
| 5～7 次 | ★★☆☆☆（2 顆星） |
| 8 次以上 | ★☆☆☆☆（1 顆星） |

> 這組數字是針對「一份內容玩 3 關、關卡難度依序遞增」這個遊戲節奏設計出來的，**不是通用常數**，套用到別的遊戲時應該依照那款遊戲實際的關卡數／預期錯誤次數分布重新設計門檻，這裡示範的原則是「答錯越少、星等越高，門檻依難度節奏切成 3-5 級」。

### 2.3 虛擬碼

```
function starsForMistakes(mistakeCount: number): number {
  if (mistakeCount === 0) return 5;
  if (mistakeCount <= 2) return 4;
  if (mistakeCount <= 4) return 3;
  if (mistakeCount <= 7) return 2;
  return 1;
}
```

呼叫時機：**只有在玩家破完全部關卡的那一刻**才呼叫一次，用「這一輪遊戲從頭到尾累計的錯誤次數」當參數，算出的星等即為這一輪遊戲的最終成績。

## 三、什麼算「一次錯誤」

明確定義「錯誤次數」的計算範圍很重要，避免遊戲邏輯跟玩家直覺的認知有落差。本例（填字遊戲）的定義：

- **算一次錯誤**：玩家把字母拖到一個「還沒被填過的正確空格位置」，但拖錯了字母。
- **不算錯誤的情況**：
  - 拖到畫面上不屬於任何題目的留白區域（不是有效格子）。
  - 拖到一個「已經填對」的格子（重複操作，不該被懲罰）。
  - 任何跟「這一格到底該填什麼」判斷無關的操作失誤（例如手滑放開手指但沒有真的拖到任何格子上）。

一般原則：**只有「玩家對這一題的答案本身做出了錯誤判斷」才算一次錯誤**，操作上的失誤（沒對準、拖到非作答區）不該被計入評分，避免玩家因為介面操作不熟悉而被扣分。

## 四、最高紀錄的儲存規則

```
function recordStars(playerId, gameId, newStars):
  currentBest = getBestStars(playerId, gameId)   // 沒紀錄過就回傳 0
  if newStars > currentBest:
    save(playerId, gameId, newStars)
  // newStars <= currentBest 時什麼都不做，保留原本的最高紀錄
```

- 用 `(玩家, 遊戲)` 這組複合鍵儲存，同一個玩家在不同遊戲各自累積獨立的最高紀錄，不同玩家之間也互不影響。
- 只有「比現有紀錄高」才更新，這是「最高紀錄」語意上的硬性規則，不是可選的最佳化。
- 星等數字要做範圍檢查（例如 `clamp(0, 5)`），避免任何上游計算異常（例如錯誤次數被誤傳成負數）寫入超出合法範圍的星等值。

## 五、UI 呈現慣例

1. **實心／空心圖示並排**：星等用「總星數個圖示」並排呈現，已達成的星等用實心圖示，其餘用空心圖示，讓玩家一眼看出「幾顆滿、幾顆空」，不需要額外看數字。
2. **沒有紀錄時不顯示這一排星星**，避免遊戲清單一開始就滿版空心星星、給玩家「還沒達成」的扣分視覺暗示；只要玩過一次（不管幾顆星）才開始顯示。
3. **遊戲內結算畫面**與**遊戲外的清單／卡片**各自獨立顯示一次星等（結算畫面顯示「這一輪玩到的星等」，清單卡片顯示「歷史最高紀錄」），兩者概念不同，不要混用同一個數字來源。

## 六、可調整、需要依專案情況重新設計的部分

把這個機制套用到別的遊戲或別的專案時，以下項目需要依實際情境重新決定，不是照抄數字：

| 項目 | 本例的值 | 需要考慮的因素 |
|---|---|---|
| 星等總數 | 5 顆星 | 依遊戲精細度決定要分幾級；級數太少會讓大多數玩家都拿到同一個星等，級數太多又會讓門檻難以拿捏 |
| 評分指標 | 累計錯誤次數 | 也可以是「用了幾次提示」「完成度百分比」等，只要是跟「有沒有掌握內容」相關、且不製造時間壓力的指標即可 |
| 累計範圍 | 全部關卡玩完才算一次 | 如果遊戲本身沒有分關卡（單局制），就直接用「這一局的錯誤次數」評分即可 |
| 門檻數字 | 0／1-2／3-4／5-7／8+ | 需要依照遊戲實際的關卡數量、單字/題目數量、預期難度重新試算，讓大多數玩家的表現能分布到中間幾個星等，不要讓某個星等幾乎沒人拿得到或幾乎人人都拿到 |

## 七、附錄：完整參考實作（TypeScript）

```ts
// ---- 星等計算 ----
function starsForMistakes(mistakeCount: number): number {
  if (mistakeCount === 0) return 5;
  if (mistakeCount <= 2) return 4;
  if (mistakeCount <= 4) return 3;
  if (mistakeCount <= 7) return 2;
  return 1;
}

// ---- 最高紀錄儲存（範例用 localStorage，實際專案可換成任何持久化方式） ----
function storageKey(playerId: string, gameId: string): string {
  return `highScores.${playerId}.${gameId}`;
}

function getBestStars(playerId: string, gameId: string): number {
  const raw = localStorage.getItem(storageKey(playerId, gameId));
  const n = raw === null ? 0 : parseInt(raw, 10);
  return Number.isFinite(n) && n >= 0 && n <= 5 ? n : 0;
}

function recordStars(playerId: string, gameId: string, stars: number): void {
  const clamped = Math.max(0, Math.min(5, Math.round(stars)));
  const current = getBestStars(playerId, gameId);
  if (clamped <= current) return; // 沒有比現有紀錄高，不更新
  localStorage.setItem(storageKey(playerId, gameId), String(clamped));
}

// ---- 遊戲流程裡的呼叫時機（示意） ----
let mistakeCount = 0;

function onWrongAnswer(): void {
  mistakeCount += 1; // 只有「判斷答案本身錯誤」才呼叫這裡，操作失誤不算
}

function onAllLevelsComplete(): void {
  const stars = starsForMistakes(mistakeCount);
  recordStars(currentPlayerId, currentGameId, stars);
  showResultScreen(stars); // 結算畫面顯示「這一輪」的星等，不是最高紀錄
}
```
